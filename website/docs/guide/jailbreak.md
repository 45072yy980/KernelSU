# 越狱模式

## 一句话

不碰 boot、不碰 system，把一个内核模块挂进**正在运行**的系统里，然后由它接管 root 能力。

## 两条提权路径

DikSU 内置两条互相独立的漏洞链，任何一条跑通，结果都一样：

| | ghostlock（CVE-2026-43499） | DirtyFrag（CVE-2026-43284） |
|---|---|---|
| 是否需要重启 | 否 | 否 |
| 依赖 | 内核版本落在受影响区间 | 内核版本落在受影响区间 |
| 稳定性 | 视机型而定 | 视机型而定 |
| 失败表现 | 停在提权阶段，系统不受影响 | 停在提权阶段，系统不受影响 |

两条链的收尾是同一个动作：模块加载完成，`ksu_late_loaded == true`，也就是管理器里说的**越狱模式**。

## 在 App 里会看到什么

- 首页出现「越狱模式」标识，并显示内核模块版本与管理器版本。
- 装模块、授权、UTS 视图、网络隔离这些页面全部可用。
- 重启后回到未激活状态，需要重新走一次提权。

## late load 带来的限制

越狱模式属于「开机之后才加载」，因此：

- 拦截范围比正常启动的 KernelSU 小一点（早于加载的进程可能看不见某些钩子）。
- 分区保护会被**强制打开**，避免在不可回滚的前提下写系统分区。
- 部分依赖「开机即生效」的模块需要在加载后再触发一次（管理器里的「重载模块」就是干这个的）。

## 失败怎么办

1. 换另一条链路再试一次。
2. 确认内核版本在漏洞影响范围内（两条链的区间不同）。
3. 都不行就说明这台设备目前没有可用路径 —— 不会损坏系统，但也没有 root。
