# 越狱模式

## 一句话

不碰 boot、不碰 system，把一个内核模块挂进**正在运行**的系统里，由它接管 root 能力。

## 两条提权路径

| | ghostlock（CVE-2026-43499） | DirtyFrag（CVE-2026-43284） |
|---|---|---|
| 是否重启 | 否 | 否 |
| 依赖 | 内核版本落在受影响区间 | 内核版本落在受影响区间 |
| 实现 | 内核写原语直接改表 | 页缓存/splice 路径拿写权限 |
| 失败表现 | 停在提权阶段，系统不受影响 | 同左 |

任意一条跑通，收尾动作都一样：加载 `kernelsu.ko`，置 `ksu_late_loaded = true`。

## 激活之后发生了什么

1. 内核模块接管 supercall，管理器能查到自己的 `MANAGER` 标志。
2. `ksud` 被拉起，负责模块挂载、授权列表、各种特性的用户态部分。
3. 分区保护**强制开启**（越狱会话没法像重启那样把分区还原）。
4. 模块在 `/data/adb/modules` 下的内容被 overlay 到系统视图里。

## late load 带来的限制

因为模块是「开机之后」才进去的：

- **早于加载的进程看不到钩子**。系统服务这类在开机时就起来的进程，可能不在拦截范围里。
- 依赖「开机即生效」的模块，需要加载后触发一次（「维护 → 重载模块」）。
- 拦截类特性（网络隔离、UTS）对新启动的进程最可靠；已经在跑的目标进程建议重启该应用。

## 失败怎么办

::: tip 先换一条链
ghostlock 不行就试 DirtyFrag，两者覆盖的内核版本区间不完全重合。
:::

1. 确认内核版本在区间内（管理器会显示当前内核版本）。
2. 关掉可能干扰的安全软件/厂商加固。
3. 都失败：这台设备目前没有可用路径。**不会损坏系统**，也没有 root。

## 常见误解

| 说法 | 实际 |
|---|---|
| 「越狱了就有 root 常驻」 | 不，重启即失效 |
| 「越狱会改 boot」 | 不，一个字节都不写 |
| 「越狱和刷机一样要 recovery」 | 不，全程在系统里完成 |
| 「失败会变砖」 | 不会，失败只是没拿到 root |
