# 诊断与求助

## 先看这三个地方

1. **设置 → 关于 → 版本详情**：三份版本并列 + 自检结论。
2. **设置 → 日志（sulog）**：每次提权的调用者、命令、结果。
3. **内核日志**：`dmesg | grep -E 'kernelsu|netisolate|uts_view'`。

## 三个版本号为什么对不上

| 版本 | 来源 | 什么时候变 |
|---|---|---|
| 管理器 | APK 自身 | 装新 APK |
| 内核模块 | 当前注入的 `.ko` | 每次越狱激活 |
| ksud | `/data/adb/ksud` | 手动替换或更新 |

越狱模式下内核模块是**每次激活时注入**的，所以它在重新激活之前不会变；`ksud` 则是随时可替换的。
三者不一致是正常的，只要管理器与内核模块的 versionCode 一致即可。

## 症状对照

| 症状 | 先查 | 处理 |
|---|---|---|
| 管理器显示「未安装」 | 内核模块版本 | 重新激活越狱；确认 APK 签名与模块匹配 |
| 应用要 root 没反应 | sulog 有没有记录 | 看该 uid 是否被授权；多用户下 uid 不同 |
| 模块装了不生效 | 模块目录里的 `disable` / `skip_mount` | 「维护 → 重载模块」，或软重启 |
| 分区保护一直拦 | 报告里的文件:行号 | 确认是不是真的要改分区；红级别无法放行 |
| 网络隔离没效果 | `dmesg \| grep netisolate` | 目标进程重启；检查 uid 与 mode |
| UTS 改了没变 | 模式/目标列表 | 看 [UTS 排查](/guide/uts#排查) |
| 重启后 root 没了 | —— | 预期行为，重新激活 |

## 导出诊断

设置 → 诊断 →「导出诊断包」，会生成一个 zip：版本、设备、引擎状态、最近错误与日志尾部。
反馈问题时附上它，比自己描述现象快得多（内容已脱敏，不含 key/token/手机号）。

## 求助渠道

- [GitHub Issues](https://github.com/45072yy980/KernelSU/issues)：附诊断包 + 复现步骤。
- 提问时写清楚：机型、系统版本、内核版本、用的是哪条提权链、哪一步失败。
