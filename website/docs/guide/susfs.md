# SUSFS

SUSFS 是内核里的一套隐藏与伪装机制，DikSU 在管理器里给了它一个完整的配置面板。

## 前提

内核必须带 SUSFS 支持。是否支持可以在面板顶部看到：显示「已加载 vX.Y.Z」才可用；
显示未加载说明当前内核没有编进 SUSFS，面板里的修改不会生效。

## 六个页签

| 页签 | 干什么 |
|---|---|
| 概览 | 加载状态、能力数量、当前规则数 |
| 设置 | 三个总开关与默认行为 |
| 路径 | 隐藏、循环、映射路径 |
| 伪装 | kstat 更新与完整克隆、伪 uname、伪 cmdline |
| 重定向 | 打开文件时改道到另一个路径 |
| 扩展 | 导入、导出、恢复默认 |

## 草稿模型

改任何一项都是**先落在草稿里**，顶部会出现「应用 / 放弃」。点应用才会写进内核，
放弃则整体回滚。这样试参数不会把系统改坏。

## 导入导出

- 导出：整份配置打包成 JSON，可以在别的设备上导入。
- 导入：先显示差异（新增几条、消失几条、开关变了几项），确认后才写入。

## 和 UTS 的关系

SUSFS 的 `set-uname` 只能改 release/version 且是全局的；需要按应用、需要改六个字段时，
用 [UTS 视图](/guide/uts)。两者同时开启时以 UTS 为准（它拦的是 `uname(2)` 本身）。
