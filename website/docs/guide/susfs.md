# SUSFS

SUSFS 是内核里的一套隐藏与伪装机制，DikSU 在管理器里给了它一个完整的配置面板。

::: warning 前提
内核必须带 SUSFS 支持。面板顶部显示「已加载 vX.Y.Z」才可用；显示未加载说明当前内核
没有编进 SUSFS，下面的修改不会生效。
:::

## 六个页签

| 页签 | 干什么 |
|---|---|
| 概览 | 加载状态、能力数量、当前规则数 |
| 设置 | 三个总开关与默认行为 |
| 路径 | 隐藏、循环、映射路径 |
| 伪装 | kstat 更新与完整克隆、伪 uname、伪 cmdline |
| 重定向 | 打开文件时改道到另一个路径 |
| 扩展 | 导入、导出、恢复默认 |

## 路径规则

| 类型 | 作用 |
|---|---|
| 隐藏（hide） | 让指定路径对目标进程不可见 |
| 循环（loop） | 同名路径在不同进程下映射到不同文件 |
| 映射（map） | 把 A 路径映射成 B 路径 |
| 重定向（redirect） | 打开时改道，适合处理 `/proc` 与 `/sys` 下的检测点 |

## 伪 uname 与 kstat

- **伪 uname**：改内核版本相关字段，全局生效。
- **kstat 更新**：文件状态（大小/mtime）跟随伪装，避免「隐藏了但 stat 露馅」。
- **完整克隆**：连 inode 元数据一起伪造，更彻底也更慢。

## 草稿模型

任何修改都**先落在草稿里**，顶部出现「应用 / 放弃」。应用才写进内核，放弃整体回滚。
试参数很安全，不会把系统改坏。

## 导入导出

- 导出：整份配置打包成 JSON，可以在别的设备上导入。
- 导入：先显示差异（新增几条、消失几条、开关变了几项），确认后才写。

## 与 UTS 的分工

SUSFS 的伪 uname 只能改 release/version 且全局；需要按应用、需要六个字段时用 [UTS 视图](/guide/uts)。
两者同时开启时以 UTS 为准 —— 它拦的是 `uname(2)` 本身。
