# 网络隔离

让选中的应用**连不上外网**，内核侧直接拒绝，不依赖 VPN、不需要装防火墙。

## 拦什么

| 操作 | 是否拦截 |
|---|---|
| `connect()` 到公网（TCP / 已连接 UDP） | 拦 |
| 未连接数据报的 `sendmsg()`（`sendto`） | 拦 |
| `AF_UNIX`、`AF_NETLINK` | 放行 |
| 回环地址 | 默认拦，可放行 |
| 私网 / 链路本地 | 默认拦，可放行 |
| `AF_PACKET` 原始套接字 | 不拦 |

被拦的调用返回 `EACCES`，应用看到的就是「网络不可用」。

## 两个例外开关

- **放行回环**：`127.0.0.1`、`::1` 可达。应用自带本地服务时打开它。
- **放行内网**：`10/8`、`172.16/12`、`192.168/16`、`100.64/10`、`169.254/16`，以及 IPv6 的 `fc00::/7`、`fe80::/10`。想只挡公网时打开它。

## 用法

1. 模式选「仅指定应用」。
2. 搜索并勾选要断网的应用（最多 128 个）。
3. 按需打开两个例外开关。
4. 点「应用配置」。

关回「关闭」立刻恢复，不需要重启。

## 风险

拦的是系统调用，应用拿到 `EACCES` 后**可能直接崩**，因为很多 SDK 不处理这个错误。建议：

- 一次只加一个应用，确认稳定再加下一个。
- 出问题立刻把模式改回「关闭」。
- `dmesg | grep netisolate` 可以看到每一笔被拦的调用（`blocked connect` / `blocked sendmsg`）。

## 命令行

```bash
ksud netisolate get
ksud netisolate set < config.json
```

```json
{
  "mode": 1,
  "flags": 3,
  "target_uids": [10123, 10234]
}
```

`mode`：0 关闭、1 仅指定应用；`flags` 位 0 = 放行回环，位 1 = 放行内网。
