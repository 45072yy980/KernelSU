# 网络隔离

让选中的应用**连不上外网**。内核侧直接拒绝系统调用，不需要 VPN、不装防火墙、不占后台。

## 拦什么

| 操作 | 是否拦截 | 说明 |
|---|---|---|
| `connect()` 到公网（TCP / 已连接 UDP） | ✅ | 返回 `EACCES` |
| 未连接数据报的 `sendmsg()`（`sendto`） | ✅ | 返回 `EACCES` |
| 已建立连接上的 `send()` | ➖ | 走 socket 里记的地址，connect 阶段已拦 |
| `AF_UNIX`、`AF_NETLINK` | ❌ 放行 | 否则应用连本地服务都会断 |
| `AF_PACKET` 原始套接字 | ❌ 不拦 | 目前不覆盖 |

## 两个例外开关

| 开关 | 放行内容 | 什么时候开 |
|---|---|---|
| 放行回环 | `127.0.0.1`、`::1` | 应用自带本地服务（播放器投屏、调试端口） |
| 放行内网 | `10/8`、`172.16/12`、`192.168/16`、`100.64/10`、`169.254/16`、`fc00::/7`、`fe80::/10` | 只想堵公网，局域网/投屏还要用 |

两个都关掉 = 除本地 socket 外全部断掉。

## 用法

1. 模式选「仅指定应用」。
2. 搜索并勾选目标应用（最多 128 个）。
3. 按需打开两个例外开关。
4. 点「应用配置」。

关回「关闭」立即恢复，不需要重启设备。

## 风险

::: danger 拦的是系统调用，应用可能直接崩
很多 SDK 不处理 `EACCES`，会当成空指针继续跑。建议一次只加一个应用，观察几分钟再加下一个；
出问题立刻把模式改回「关闭」。
:::

## 排查

```bash
dmesg | grep netisolate
# netisolate: blocked connect for uid 10123
# netisolate: blocked sendmsg for uid 10123
```

- 有日志、应用却还能上网：目标进程在隔离生效前就建立了连接（重启该应用）。
- 没日志：uid 没对上（多用户/工作资料），或者应用走了系统代理。
- 页面显示「当前内核不支持」：内核模块没加载。

## 命令行

```bash
ksud netisolate get
ksud netisolate set < config.json
```

```json
{
  "mode": 1,
  "flags": 3,
  "target_uids": [10123, 10234]
}
```

`mode`：0 关闭 / 1 仅指定应用。
`flags`：位 0 = 放行回环，位 1 = 放行内网（`3` 表示两个都放行）。
