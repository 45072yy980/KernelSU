## 十、netisolate 三层落地（2026-11-07）

`c935d0773`，CI #8（run 42330629350）六个 job 全绿。

| 层 | 文件 |
|---|---|
| 内核 | `kernel/include/uapi/netisolate.h`、`kernel/feature/netisolate.c/.h`、`supercall/dispatch.c`、`core/init.c`、`Kbuild` |
| ksud | `userspace/ksud/src/netisolate.rs`、`cli.rs`（`netisolate get\|set`）、`ksucalls.rs` |
| 管理器 | `data/netisolate/NetisolateRepository.kt`、`ui/screen/netisolate/NetisolateScreen.kt`、`Route.Netisolate`、设置页入口 |

要点：

- 挂在 LSM 的 `socket_connect` 上（`KSU_LSM_HOOK_INIT`，与 `selinux_hide` 同一套框架），
  SELinux 一定注册了这个钩子，所以链里必然有槽位
- 拦 `AF_INET`/`AF_INET6` 的 `connect` 与未连接数据报的 `sendmsg`；`AF_UNIX`、`AF_NETLINK`
  放行，否则应用连本地服务都会断
- 配置：`mode`（0 关 / 1 仅目标应用）+ `flags`（放行回环 / 放行私网）+ 最多 128 个 uid
- 热点路径一次 `atomic_read` 就放行；查表进 RCU 读区；更新配置换指针 + `synchronize_rcu`
- 钩子装不上时 `supported=0`，管理器显示「当前内核不支持」，写配置不会假装成功
- UDP `sendto` 的缺口已由 `socket_sendmsg` 补上（`b066d02a`）；仍不拦原始套接字（AF_PACKET）

**sendmsg 的坑（已踩过）**：`KSU_LSM_HOOK_INIT(socket_sendmsg, "selinux_socket_sendmsg", ...)`
里 head 名是 `socket_sendmsg`（不是 `sendmsg`），而目标符号是 `selinux_socket_sendmsg`；
只有 `msg->msg_name != NULL`（未连接）时才拦。装不上时退回 connect-only，不算不支持。

**真机验证清单**（本机没有设备，一条都没跑过）：

1. `ksud netisolate get` 应该返回 `"supported": 1`；为 0 说明钩子没装上
2. 选一个应用 + 关闭两个放行开关，`ksud netisolate set` 后该应用应立刻连不上外网
3. 打开「放行回环」，应用自建本地服务仍可用；打开「放行内网」，局域网设备仍可达
4. 关回 `mode=0` 后网络立即恢复（不需要重启）
5. 观察 `dmesg`：`netisolate: blocked connect for uid N` 只应出现在目标 uid 上
